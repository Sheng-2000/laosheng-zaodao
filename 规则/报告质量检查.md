## 一、数据及时性检查

**检查时机**：所有其他检查之前必须首先执行
**不通过处理**：发现旧数据立即打回，重新搜索替换

### 1.1 关键日期定义

**⚠️【最高优先级·2026-11-05 修订】数据日期口径改为「最新可得数据」**：报告日期 = T 日；数据日期 = 截至生成时刻最新可得数据——该市场当天已收盘即取当天收盘，未收盘或休市则取最近一个已收盘交易日并标注日期与「休市」；所有行情、新闻、政策、机构观点、产业动态、社区素材、事件、日历、估值、理财参考一律取最新可得，不同市场按各自最新可得时点逐项标注快照日期，禁止用旧数据冒充当日数据。本清单下文所有「T-1 日数据 / T-1 日收盘 / T-1 日 / T-1 日市场」检查项一律按本条解释：核验的是「是否为该市场最新可得收盘数据且已标注快照日期」，而非机械等于 T-1；「标题与正文同源」改为报告日期 = T 日、数据截止日期 = 最新可得口径日期，并须含「最新可得数据」口径说明。

- **报告日期** = T日（如5月21日）
- **数据日期** = T-1日（如5月20日）
- **模板旧日期** = 规则/template.html中残留的日期

### 1.2 自动化检测

**检测步骤**：

1. 检查旧日期残留（T-3日及更早，输出应≤3处）
2. 验证新数据已写入（关键数据出现≥10处）
3. 检查数据一致性（同一指标在不同位置应相同）

### 1.3 判定标准

| 检查项 | 通过标准 | 不通过信号 |
| --- | --- | --- |
| 旧日期残留 | ≤3处（仅允许合理历史回顾） | \>3处 |
| 新数据覆盖 | ≥10处关键数据 | \<5处 |
| 数据一致性 | 同一指标全报告一致 | 同一指标不同值 |

## 附：高亮适度化最终口径（v2.19 · 优先级最高）

来源：2026-11-06 用户反馈「重点高亮展示也要适度，不能颜色太多，反而失去了重点」。本节为**覆盖条款**：本文档及《报告生成规范》表格/清单中任何「≥5处/张」「每张≥5处高亮」「4-6处」「5处硬门槛」「每条需5处」等旧凑数指标一律作废，以本节为准。

- 🔴 红 / 🟢 绿是唯一承载涨跌方向的重点色，必须占视觉主导；🔵 青色只标真实金融关键术语（红利/高股息/股息率/估值/利率/收益率/美债/美联储/降息/加息/非农/汇率/美元/油价/金价/流动性…）与中性数字、口径标注；🟡 黄 / 🟠 橙从严，每卡 ≤1 处。
- 🚫 严禁为凑数量而刷色：不得给通用名词（市场/政策/数据/公司/板块/指数/影响/情况…）着色，不得包裹随机两字中文词，不得把相邻词连续染色形成「彩色大段」，不得把同一句里的多个数字逐一染青，不得用青色凑满每卡下限。
- 数量口径：每卡 2–4 处即可，不必凑满。新闻/AI/生物医学卡下限 2、上限 5；社区话题观点 4；其他叙事卡 2–3。下限只是为避免完全无重点，绝不是「必须刷到 N 处」。
- 全篇密度基准 ≥50 字/处；低于 45 字/处即过密须削减（青色先摘，其次无数字的黄/橙，带数字的红/绿最后摘）。参考实测：适度化后单期约 红200 / 绿145 / 青169 / 黄58 / 橙13；若青色接近或超过红绿合计，即判刷色须重做。
- 配套质检脚本口径（本地路线）：qc\_check 全篇高亮 span 下限 240；cover\_qc / deep\_qc 新闻·AI 卡每卡下限 2；hl\_boost.py 已移除通用名词与随机两字词兜底。云端路线以定时任务提示词 §三 3a 为准。
