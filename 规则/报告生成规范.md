## 一、生成流程（铁律）

### 1.1 日期确定与数据时效策略（生成前必须执行）

```
步骤1：获取互联网中当前中国时区的日期，确认为 T 日（如 2026-05-25）
步骤2：文件名日期 = T 日（如 20260525）
步骤3：header 显示 T 日日期
```

**⚠️ 数据时效策略（严格执行，按Tab区分）**：

| Tab              | 数据时效策略 | 说明                                      |
| ---------------- | ------ | --------------------------------------- |
| **Tab 0 要点速览**   | 当下最新   | 搜索最新新闻/事件，不限定日期                         |
| **Tab 1 国内外新闻**  | 当下最新   | 搜索最新国内外新闻，取生成时刻前最新报道                    |
| **Tab 2 AI前沿**   | 当下最新   | 搜索最新AI/科技动态，取生成时刻前最新报道                  |
| **Tab 3 全球市场**   | 最近收盘日  | A股/港股/美股/亚太/欧洲/大宗/加密/汇率债券，均取最近一个交易日收盘数据 |
| **Tab 4 价值投资风向** | 当下最新   | 机构观点、板块估值取最新可得数据                        |
| **Tab 5 关注标的**   | 最近收盘日  | 股价/涨跌幅取最近交易日收盘数据，基本面取最新可得               |
| **Tab 6 理财话题**   | 当下最新   | 存款利率、理财收益率、社区话题取最新可得数据                  |
| **Tab 7 今日总结**   | 当下最新   | 综合分析取最新可得数据                             |

**搜索关键词策略**：

- **全球市场数据（Tab 3/5 股价部分）**：使用"动态数据日期"（见上方判定表）搜索，如"2026年11月4日 A股收盘"；数据日期由生成时刻动态决定，严禁写死 T-1。
- **其他所有 Tab**：不限定具体日期，搜索最新信息，如"最新央行MLF操作""AI大模型最新进展"

**⚠️ 全球市场数据日期（核心规则：动态取"最近一个已收盘交易日"，严禁写死 T-1）**：

| 生成时刻（北京时间） | 数据日期（最近一个已收盘交易日） | 报告标注示例 |
|------|--------------------------------|------------|
| ≥ 当日 15:00 且当日为交易日（周一至周五，非假期） | **当日收盘（T日，即 T+0）** | "11月5日收盘（周四）" |
| < 当日 15:00（常规早间生成，如 07:00） | 最近一个已收盘交易日（多为前一交易日 T-1；周一早间为上周五 T-3） | "11月4日收盘（周三）" |
| 周末生成 | 最近交易日收盘 | 标注"周末休市" |
| 法定假期生成 | 最近交易日收盘 | 标注"假期休市" |

- A股/港股 15:00（北京时间）收盘；美股按美东上一交易日（对应北京时间次日凌晨/上午）。
- 早间（<15:00）生成时当日尚未收盘，自然取前一交易日收盘——这是**动态判定**的结果，而非写死 T-1。
- **若日后把生成时间改到 15:00 之后，同日报即可自动取当日收盘（T+0），无需改代码/改约定。**

### 1.3 撰写报告（基于规则/template.html）⚠️核心流程

**⚠️ 铁律：必须基于 规则/template.html 复制后填充，严禁从零生成HTML文件！**

**🚫 唯一合法起点 = 规则/template.html（空占位符骨架）。严禁用上一期已完成的成品报告（如 老盛早知道_YYYYMMDD.html）作为生成起点，也严禁 `cp 上一期 + 改数值/改日期` 的轻量路径。** 历史教训：8/18 报告用 cp 上一期（锁 8/14 数据）改数值生成，结果资讯区 81% 文字照搬、且出现"缩量分化"实为放量普涨等方向反向硬伤。今后**所有信息（市场数据、新闻、AI动态、机构观点、社区话题、操作建议）每期都必须联网重新搜索并重新撰写**，不允许从任意已完成报告中提取或复用任何文字内容——哪怕是"只改数值"也不行，因为成品报告里的资讯/描述文字同样会跟着被沿用。

**操作步骤**：

```
步骤1：复制模板（必须用命令复制，不能手动重写）
  cp 规则/template.html 老盛早知道_YYYYMMDD.html

步骤2：读取复制后的文件，确认文件结构完整（8个tab-panel、CSS/JS未损坏）

步骤3：根据获取的内容更新各个tab的内容
  ** 内容丰富度要求（严格执行）**：
  - 禁止简单描述，更新内容必须丰富，每个占位符的描述至少包含100字以上，提供背景信息、市场影响、投资逻辑
  - **下限之外还有上限**（见 §1.5）：普通长段 260–320 字，超过 400 字即视为冗余，须删句而非改词
  - 下面4个区域的内容必须丰富，里面每个占位符的描述都达到120字以上：一 · 机构价值投资观点、三 · 高股息板块深度分析、社区热门话题、今日操作建议
  - 关注标的 内容需要丰富一些，体现以下信息：利好、优势、利空、风险、警示、注意 等 

  ** 重点突出展示要求（严格执行）**：
  - 文字内容重点必须通过 **颜色高亮** 突出，不改变字体大小
  - 上涨/利好/正面关键词 → 红色 (`#f85149`)
  - 下跌/利空/负面关键词 → 绿色 (`#3fb950`)
  - 例如："<span style=\"color:#f85149;font-weight:700;\">大涨2.84%</span>创历史新高"
  - **高亮处数与段落长度按 §1.5 预算执行**：宁少勿多，一段里到处是重点等于没有重点

 ** 替换操作要求（严格执行）**：
  - 禁止删除、新增、修改任何HTML标签
  - 禁止修改CSS样式
  - 禁止修改JavaScript代码
  - 只允许修改占位符中的文本内容

步骤4：根据真实涨跌数据，调整全球市场卡片的 class 和边框颜色
  - 上涨 → class="up"（红色）
  - 下跌 → class="down"（绿色）
  - 持平/无数据 → class="neutral"（灰色）
  - 卡片边框颜色同步调整
```

**占位符替换规则**：

| 占位符类型   | 替换方式                                                             | 示例                                                                             |
| ------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 纯数据类    | 直接替换为数值                                                          | `{{A股_上证指数_数据}}` → `4112.90 +0.87%`                                            |
| 文字描述类   | 替换为详细描述，特别是如下4块内容需要特别详细：一 · 机构价值投资观点、三 · 高股息板块深度分析、社区热门话题、今日操作建议 | `{{新闻1_正文}}` → 具体新闻内容                                                          |
| 涨跌class | 根据真实数据选择up/down/neutral                                          | `class="neutral"` → `class="up"`                                               |
| 卡片边框    | 根据整体涨跌调整颜色                                                       | `border-top:2px solid rgba(255,255,255,0.12)` → `border-top:2px solid #f85149` |

**禁止行为**：

- ❌ 严禁从零生成HTML文件（必须cp 规则/template.html）
- ❌ **严禁用 Write 工具一次性写入整个文件**（会把模板的 CSS/JS 结构覆盖掉，导致文件损坏）
- ❌ 严禁修改HTML标签结构（只替换占位符内容）
- ❌ 严禁修改CSS样式代码
- ❌ 严禁修改JavaScript代码
- ❌ 严禁删除或新增占位符（如需调整请先修改规则/template.html）

**⚠️ 填充方式铁律（严格执行）**：

```
正确做法：一个卡片/区域一个卡片/区域地更新
  1. 保持 HTML 标签结构完全不变（<div class="tab-panel">、<div class="card"> 等标签不动）
  2. 只替换标签内部的文本内容（如卡片标题、正文、数据值）
  3. 可以按区域批量替换，例如：
     - 一个卡片一个卡片替换（替换 <div class="card-body">...</div> 内部内容）
     - 一个概览卡一个概览卡替换
     - 一个市场数据行一个数据行替换
  4. 逐个 Tab 完成，顺序：Tab 0 → Tab 1 → Tab 2 → Tab 3 → Tab 4 → Tab 5 → Tab 6 → Tab 7
  5. 最后统一检查涨红跌绿和文字高亮

错误做法（绝对禁止）：
  - 用 Write 工具一次性写入整个文件 ❌
  - 替换包含 HTML 标签的整个区域（如从 <div class="tab-panel"> 到 </div>）❌
  - 修改/删除/新增任何 HTML 标签 ❌
  - 用脚本批量替换后整体覆写文件 ❌
  - 任何可能导致 CSS/JS/HTML 结构被覆盖的操作 ❌
```

### 1.3.5 资讯区刷新铁律（严格执行）

- ❌ **严禁直接照搬上一期报告的资讯文字**（新闻/AI/社区/观点类 `card-body`）当作本期内容。历史教训：8/18 报告曾 81% 资讯卡与 8/17 报告一字不差，且 8/17 本身锁更早数据，导致大量陈旧甚至方向反向的错误（如"缩量分化"实为放量普涨、"净流出2200亿"实为净流入、恒科写-1.77%实为+1.58%）。
- ✅ **每次生成必须联网搜索「数据日期当日 + 最近一个周末」的重大事件**，刷新 Tab 0/1/2/4/6/7 的突发类卡片（政策会议、经济数据、央行操作、地缘突变、大模型/算力动态、社区当日热门）。
- ✅ **内容分层处理**：
  - 产业趋势类（AI开源生态、脑机接口政策、国产替代、HBM短缺等中长期逻辑）：可跨期复用，但须核实仍为最新，有更新进展须补充；
  - 机构观点类（券商/投行中长期研判）：可跨期复用，但须确认观点仍有效、无反向新证据；
  - 突发/事件类（地缘、并购、财报、具体数值）：**必须取当期最新，禁止沿用旧期**。
- ✅ **必查项**：生成后用脚本对比本期与上期报告的 `card-body` 文本重合率，若 >70% 且非产业趋势合理复用，判定为「照搬未刷新」，须补搜当期新闻。
- 🚫 **绝对禁止轻量路径（`cp 上一期成品 + 改数值/改日期`）**：此路径是 8/18 报告的翻车根因——以为"改完市场数值就更新了"，实则资讯区 81% 文字照搬、还混入方向反向旧数据。今后**任何情况都不允许**使用此路径，唯一合法起点永远是 规则/template.html 空骨架。
- 🚫 **即使市场数据部分，也必须联网重新核实**：禁止沿用上一期报告中的具体点位/涨跌幅/估值数值（如"上证3982.65"等），每期重新搜索"动态数据日期"收盘数据填充，避免旧数值残留。

### 1.5 重点密度与详细度预算（严格执行）

> 来源：2026-11-03 用户反馈「1、内容过于详细了 2、颜色重点表示 颜色太多了，重点画的太多，容易失去重点」。
> 该反馈针对的是 20261030 / 20261031 / 20261103 三期一路加码的"信息量竞赛"——单期叙事字数堆到 9.3 万、
> 颜色标记 2399 处、平均 38.9 字就有一处高亮，结果是满屏重点、读者抓不到主次。以下预算为长期生效的硬约束。

**（一）高亮处数预算**

| 卡片类型 | 高亮处数 | 说明 |
|---|---|---|
| 一般叙事卡（综评/观点/话题/理财/总结各段） | **上限 3 处**，下限 2 处 | 只给"方向 + 极值 + 关键数"，其余回正文 |
| Tab 1 重点新闻卡、Tab 2 AI 卡、生物医学卡 | **5 处**（cover_qc 硬门槛，不可低于） | 质检要求，属例外 |
| 社区话题 N _观点 | **4 处**（cover_qc 硬门槛，不可低于） | 质检要求，属例外 |
| 全篇合计 | 目标 ≤ 900 处标记（≈1200 个高亮 span） | 本期实测 1125 标记 / 1241 span / 53.1 字每处 |

> **预算按"数据键"计，不按渲染卡片计。** 一个占位符键 ≤3 处；一张渲染卡若由多个键组成（如 Tab 3 的资金面板卡、
> 隔夜美市卡由 5–7 个键拼成），单卡出现 18–21 处是正常的，只要每个键各自 ≤ 上限即可。
> 用 `python3 脚本/demark_highlight.py` 干跑（触及键 0）来判定，不要用肉眼按卡数。
> 全篇密度基准：**≥ 50 字每处**；低于 45 字/处即说明重点画得过密，须回头削减。

**（二）颜色分配（五种颜色各有唯一职责，不得混用）**

- 🔴 红 / 🟢 绿：**唯一的方向色**，只标涨跌、利好利空、资金进出。带数字的方向标记优先级最高，永远保留。
- 🔵 青：**只用于"不是方向"的中性信息**——口径标注（不复权、交易所/东财/Wind 口径、快照时点、停披）与中性数据陈述
  （排名窗口、分母、比较值，如"年内收盘第X位""较年内高点差X%"）。**不得**用于涨跌方向。
  反过来也一样：凡是"跌/回落/下行"的方向词不能整段留在红 span 里，"涨/普涨/最高收盘"也不能整段包在绿 span 里——
  遇到"涨了很多但仍是年内低位"这类混合句，**颜色只给真正结论的那半句**，另一半回正文。
  已发布各期的惯例：美债收益率下行、美元指数收跌 → 青色；"三大利空出清、预测V型反转"这类乐观研判 → 红色（正面=红）。
- 🟡 黄：警示与"注意/不确定"，每卡至多 1 处。
- 🟠 橙：次级重点（连板、政策落地日），仅在同卡红绿已满时使用。

降色量用已固化的 `脚本/demark_highlight.py`（默认干跑，逐键打印超预算项，加 `--write` 才落盘）：
超过每卡上限时按优先级削减——青色总是先摘，其次无数字的黄/橙，带数字的红/绿最后摘；
只对纯可见字数 ≥150 的键动手，短键保持原样。每期填写完 g_data 后先干跑，再 `--write`，然后 build。
**干跑输出"触及键 0"即为本期已符合预算。**注意 cap 对新闻/AI/生物医学卡取 5、社区观点取 4，
正好等于 cover_qc 的硬门槛，所以按此削减不会把任何卡摘到质检线以下。

**（三）详细度预算与压缩方法（可验证，不允许凭感觉删）**

- 长叙事段目标 **260–320 字**；≥400 字的键一律列为待压缩项。
- **只能"整句删除"**：保留下来的每一句必须与原句逐字相等（只可删句首连接词），禁止改写、禁止缩写、禁止拼接。
  这样做的目的是把主观的"太详细"变成机器可校验的变换——压缩前先把 897 键原文快照存盘
  （本期：`/tmp/orig_keys_20261103.json`），压缩后跑 provenance 校验：
  ① 每个保留句必须是原值的子串；② 每个出现的数字串必须能在原值里找到。两条全过才算合格。
- **删句优先级**：先删"复述同一事实的第二种说法"和"没有新增信息的过渡句"，
  **必须保留**：数据日、口径限定词、极值断言的分母与排名、以及任何"未经确认/单一来源"之类的可信度限定。
  历史翻车案例（务必避免）：压缩时把 `顶部描述` 里"央行会同金监总局、证监会稳市座谈会——官方通稿确认落地"
  整段删掉，等于删掉了全篇最重要的政策事实；也出现过删句后主语丢失、前后自相矛盾
  （"都不在年内高位"与"仍在年内前10高位"）。**压缩后必须人工抽读 ≥7 个键。**
- 元数据与标签（`*_收盘日期`、卡片标题、`市场综评_日期` ≤19 字）不参与压缩。

**（四）交付前复核**

- 五套质检全 PASS 只是必要条件；高亮**语义**（红=涨、绿=跌、青=口径）必须再独立回读一遍，脚本绿 ≠ 没问题。
- 检查一次"每卡高亮是否 ≤ 预算"，把超预算的卡当场摘回 3 处。

## 二、数据引用规范（铁律）

### 2.1 数据时效性要求

| 数据类型    | 要求             | 示例                     |
| ------- | -------------- | ---------------------- |
| 价格/指数数据 | 必须引用最新可得日期     | "标普5/12收盘7412.84"      |
| 基本面数据   | 可引用最近可得，必须标注来源 | "截至2025年报"             |
| 政策/事件   | 必须引用最新进展       | "美联储5/7决议"             |
| 利率/国债   | 引用最新可得         | "1年定存1.65%（2026年5月数据）" |

### 2.2 禁止行为

- ❌ 严禁编造数据
- ❌ 严禁使用过期数据冒充当日数据
- ❌ 严禁"银行护盘"等无来源说法

### 2.3 数据标注格式

- 价格数据：`"标普5/12收盘7412.84（+0.19%）"`
- 基本面数据：`"截至2025年报：归母净利润3685.62亿元"`
- 未披露数据：`"一季报尚未单独披露（最新数据截至2025年报）"`

**涨跌颜色规则（A股惯例，严格执行）**：

- 🔴 **上涨/利好/正面** → 红色（`#f85149` / `var(--red)` / `class="up"`）
- 🟢 **下跌/利空/负面** → 绿色（`#3fb950` / `var(--green)` / `class="down"`）
- ⚪ **持平/中性** → 灰色（`class="neutral"`）
- 🔵 **中性信息/数据** → 蓝色（`#00d4ff` / `var(--accent)`）
- 🟡 **警示/关注** → 黄色（`#f0b429`）

**常见易错场景**：

- "大涨X%"、"创新高"、"领涨" → 必须用**红色**，不能用绿色
- "大跌X%"、"净卖出"、"暴跌" → 必须用**绿色**，不能用红色
- "偏悲观"、"恐慌"、"谨慎" → 必须用**绿色**（负面=绿色）
- "偏乐观"、"信心"、"看好" → 必须用**红色**（正面=红色）
- "外围市场上涨"相关卡片背景和文字 → 用**红色**系，不能用绿色系
- 涨跌幅数值（如+3.14%、-2.04%）→ 上涨红色、下跌绿色
- 标签（如"今日领涨"）→ 红色背景+红色文字
